# Control Vision user guide

## Prepare a local install

Use Python 3.11 or newer, install the pinned packages in `requirements.txt`, and run `python -m control_vision`. Accurate full-match robot detection requires a locally trained YOLO model with class 0 named `robot`; Control Vision does not download weights. A seeded optical-flow preview is available without a model, but it is not accurate enough for scoring or unattended identity attribution. Highlight clips use the FFmpeg binary bundled with the pinned `imageio-ffmpeg` package, and the packaged Windows build includes FFmpeg. To use a different FFmpeg build, set its path in Settings or put `ffmpeg.exe` on PATH; either overrides the bundled binary.

## Analyze a practice video or match

1. Create a project in a folder or reopen its `control_vision.sqlite` file.
2. Import an MP4, MOV, or MKV. Enter the optional event code and match number. Low resolution and low frame rate produce warnings but do not block import.
3. Choose a clear field frame and click the field corners clockwise, starting at the top-left. The points map to a 12 by 12 foot square. Reuse Calibration copies a previous video calibration and scales the corner pixels to the new resolution; visually confirm it before processing.
4. On the top-down map, choose a zone type and Draw Zone. Click polygon vertices and double-click to finish. Use names that match the field manual. No default zone coordinates are supplied because the manual diagram was not included.
5. Seed each visible robot by clicking near its floor contact point, then enter the team number and alliance. Up to four robots are supported. Seeds are matched to detected robots only during the first 3 seconds of the video, so seed robots that are clearly visible then. If no seed matches a detected robot in that window, processing stops right away and reports, for each click, how far the nearest tracked robot was, or that a robot was detected with too little confidence to be tracked. Reseed on robots that are clearly visible at the start.
6. Set the tracking method, model path, confidence threshold, and sample rate under Settings, then press Process. YOLO is the intended detector when a validated local model is available. Seeded optical flow shows experimental trails only and omits cycles and movement statistics. It never guesses identity: a robot that is lost, occluded, or too close to a same-alliance robot records no positions until one clear match brings it back, so trails can have gaps or be empty. If no seeded robot records a position, the run is marked as not analysed; if some robots record none, the app names them. The preview sample rate is 5 to 10 frames per second, and seed points must lie inside the video frame. Cancel stops after the current frame. Logs go to `run_logs/`.
7. To read the final on-video scoreboard, seek to a frame showing the final results screen, then draw tight red and blue score ROIs around those final score digits in Analysis. Broadcasts may move the score between the live overlay and the final screen. Open Export and run the OCR proposal. Review its values and readable-frame count before choosing Use OCR reading. This stores proposed official totals; it does not create per-robot scored events.

## Interpret results

The trail view follows the playable video timeline. Cycles are pickup-to-scoring zone trips and carry medium confidence because the current pipeline does not detect game pieces. Each scoring-zone trip creates a zero-point flagged candidate. You can also add a candidate at the current video time for events such as a HIVE tip or PARK. In Review Queue, select the event type, adjust the point count, set confidence, confirm/reject it, and reassign the robot if needed. The event-type presets follow BIOBUZZ Competition Manual TU09; visual evidence still needs human interpretation. Only confirmed points contribute to video totals. Enter the official red and blue alliance totals to compare them. The match remains labeled unreviewed while any flagged events remain.

In Export, set the match type and enter only the Head Referee's disqualification ruling from the official record. For a Qualification match, tick the DQ box for each disqualified team: that team gets 0 match points and 0 Ranking Points, and its alliance partner keeps its points and Ranking Points (T601). For a Playoff match, tick the alliance DQ boxes instead: a DQ applies to the whole alliance, and playoffs award no Ranking Points (13.7). If both alliances are disqualified, choose which alliance was disqualified first or that the DQs were simultaneous (T705); until you do, the result shows as pending a referee ruling. Mark a playoff match final after reviewing every event so the reviewed score decides the winner or tie. Changing the match type asks before clearing rulings that do not apply to the new type.

Generate highlight clips after processing. Clips cover up to three seconds before and after each non-rejected candidate; boundary clips are shorter at the start or end of the video. Double-click a review row to preview its clip, or jump to the source video when no clip exists.

Statistics CSV and Scout JSON exports use the reviewed database values. Official scores are alliance totals, so the Scout team's `points_official` remains null rather than repeating an alliance value for every robot. Both exports add the match type, each team's DQ state and, for playoffs, the result (win, loss, tie or pending); the Scout JSON also carries the full ruling and playoff outcome. Ranking Points are exported for qualification matches only. Robot PNGs use the largest tracked crop, with confidence as the tie-breaker and a 20% margin. Crops smaller than 200 by 200 pixels are skipped and logged.

## Known verification limits

No trained weights, labeled dataset, or holdout videos ship with the source. The UI and code do not claim measured ID-switch, track-completeness, cycle-count, scoring, or CPU-performance results. Zone crossings and manually reviewed points are practical scaffolding; score-value inference from robot motion alone is not automatic.

On the Salk Q3 clip, ROIs copied from the live overlay proposed 156–93, which differs from the official 180–103 result. The final results screen moves the scores. ROIs drawn around the final screen's digits proposed 180–103 on the last-12-second window. The red score animates in on that screen (its 4 readable frames read 8, 8, 18, 180); OCR treats 8 and 18 as partial reveals of 180, but only one frame shows 180, so red is flagged at 26% confidence. Blue 103 comes from 2 readable frames and is flagged at 54% confidence. A flagged proposal is shown as low confidence; check the final score on the video before using it. This single clip does not establish general OCR accuracy, and every proposal requires review.

On the same clip the seeded preview records very few positions. With one blue and one red seed at 8 fps, the blue robot produced 23 positions in the first 3 seconds and none after that, and the red seed produced none because no red alliance colour was found near the click. The app names robots without positions after processing, and marks a run where no robot produced a position as not analysed.
